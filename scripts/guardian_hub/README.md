# 監視ハブ（接続ゲートと監視 AI）

ロボットをインターネットにつながずに、2 つのことをします。

1. **接続ゲート**：ロボットのつながり方を、その時々で開け閉めします。単独、店内ネットワーク、インターネットの 3 段階です。
2. **監視 AI**：全部のロボットの動きを見比べて、その場で動き方を直します。故障したロボットがあれば、誰が向かうとよいかも推薦します。

```
 単独（ロボット）           │扉1│      店内ネットワーク（この PC）        │扉2│   インターネット
 Unity のロボット A・B・C ◀──┼───┼──▶ hub.py（監視 AI・推薦）            ──┼───┼──▶ Google Drive の同期フォルダ
 GuardianHubLink           │   │    127.0.0.1:47612 だけ                │   │   （記録を書くだけ）
 速度の上限を守る           │   │                                        │   │
 閉じるのは自動、開けるのは人                                        開けるのは人、閉じるのは自動
```

| 扉 | 場所 | 閉じる | 開ける |
|---|---|---|---|
| 扉 1（ロボット ⇄ 店内） | Unity（`GuardianHubLink`） | 使えない助言が 10 秒に 3 回届いたら自動で閉じる。人が「単独にする」を押しても閉じる | 人が理由を確かめて「店内に戻す」を押したときだけ |
| 扉 2（店内 ⇄ インターネット） | ハブ（`hub.py`） | 記録を書き出したら自動で閉じる。書き出せなければ `--external-minutes` 分で閉じる | 人がハブで `open` と打ったときだけ |

扉 1 が閉じている間も、ロボットは Unity の中でいつもどおり動きます。ハブを起動しないときも同じです。

## 監視 AI がすること

| 見つけたこと | 判断 | すること |
|---|---|---|
| 同じ場所で 2 台以上が揺れた | 場所の問題（床の段差など） | その場所（半径 1.8 m）を通るときの速度上限を 0.6 倍にする |
| 1 台だけが、場所を変えても揺れる | 機体の問題 | そのロボットの速度上限を 0.7 倍にし、点検を勧める |
| しばらく揺れがない（`--relax-after` 秒） | もう戻してよさそう | 元に戻す**提案**だけを出す。戻すかどうかは Unity で人が決める |
| ロボットが止まった、制限になった、荷物を載せたまま 30 秒動かない | 人が行くべき故障 | 役割の合う人から、店内の点と通り道のグラフ上の最短経路（ダイクストラ法）で、早く着く順に 1 位と次点を推薦する |

- 「揺れた」は、ロボットごとに学んだふだんの値（指数移動平均）より 0.15 大きいとき、または 0.30 以上のときです。起動してから `--learn-seconds` 秒は学ぶだけで、何もしません。
- 厳しくするのは AI、緩めるのは人です。ネットワークからは速度を下げることしかできません。Unity は、速度を上げる指示や範囲外の値を使わずに捨てます。
- 推薦は命令ではありません。段差がありそうな場所を通る道は、歩くのにも時間がかかるものとして計算します。手がふさがっている店員は 30 秒遅れて着くものとします。
- 判断のしかたは決まった規則と統計です。学習済みのモデルは使っていません。だから、なぜその判断になったかを毎回文章で示せます。

## 起動

Docker で動かす方法（記録・画面・扉 2 のコンテナ・Unity の代役つき）は [core/README.md](../../core/README.md) にあります。ここは Docker を使わずに動かす方法で、Docker が動かないときの予備にもなります。2 つは同じ 127.0.0.1:47612 を使うので、同時には動かしません。


Python 3.10 以上だけで動きます。追加のパッケージは要りません。USB の機器（M5StickS3、PSoC 6）は開かず、M5StickS3 にも書き込みません。センサー中継と共有中継とは同時に動かせます。

macOS:
```bash
python3 scripts/guardian_hub/hub.py --drive-dir "$HOME/Google Drive/My Drive/robomori"
```
Windows（PowerShell）:
```powershell
py scripts\guardian_hub\hub.py --drive-dir "G:\マイドライブ\robomori"
```

そのあと Unity で Play を押します。Unity が 127.0.0.1:47612 に自分からつなぎにいきます。順番はどちらが先でもかまいません。右側の表示板の下に「監視AI・接続ゲート」の枠が出ます。

ハブのウィンドウで打てるコマンド：

| コマンド | すること |
|---|---|
| `open`（`o`） | 扉 2 を開けて、記録を `--drive-dir` に書き出す。書き終えたら自動で閉じる |
| `close`（`c`） | 扉 2 を閉じる |
| `drill`（`d`） | 扉 1 の訓練（模擬）。Unity が捨てるはずの助言（速度を上げる指示、順番が戻った助言、途中で切れた JSON）を 0.4 秒おきに送る。Unity は 3 回捨てた時点で扉 1 を自動で閉じる |
| `status`（`s`） | 扉、減速、提案、推薦、捨てた行の数を表示する |

発表で、段差による減速を短い時間で見せるとき：
```bash
python3 scripts/guardian_hub/hub.py --simulate-bump 通路中 --learn-seconds 10 --relax-after 60
```
`--simulate-bump` で指定した場所を通るロボットの揺れに 0.35 を足します（模擬です）。記録と理由にも「模擬の段差」と書きます。

| オプション | 既定 | 内容 |
|---|---|---|
| `--port` | 47612 | 待ち受けるポート。Unity 側は `-robomoriHubPort=` で合わせる |
| `--drive-dir` | なし | 扉 2 で書く場所（Google Drive for desktop の同期フォルダ） |
| `--external-minutes` | 5 | 扉 2 を開けておける最長の時間（分） |
| `--learn-seconds` | 20 | ふだんの揺れを学ぶだけの時間（秒） |
| `--relax-after` | 120 | 揺れがこれだけ続かなければ、戻す提案を出す（秒） |
| `--simulate-bump` | なし | 模擬の段差を置く場所（何度でも指定できる） |
| `--log-dir` | `Logs/guardian_hub` | ハブの記録 |

## PV と同じ流れでデモを見せる

[PV](../../pv/README.md) の 0:31〜0:51 で見せたことを、Unity でそのまま見せる手順です。デモの映像を録って PV のあとにつなぐときにも使えます。

1. ハブを起動して、Unity で Play を押す。
   ```bash
   python3 scripts/guardian_hub/hub.py --simulate-bump 通路中 --learn-seconds 10 --relax-after 60 --drive-dir <Google Drive の同期フォルダ>
   ```
2. **監視 AI が速度を下げる**：10 秒学んだあと、通路中を通ったロボットが揺れたと判断され、枠に「通路中　速度上限 ×0.6」が出る（30 秒ほど）。
3. **対応のおすすめ**：Unity でロボット C を止める（例：3 キーで C を選んで E キー）。枠に「C　停止（保持）→ 保守担当（約 ◯ 秒）」が出て、床に緑の経路が描かれる。
4. **扉 1 は自動で閉じる**：ハブで `drill` と打つ。Unity の枠に「使えない助言を捨てた」が 3 回出て、扉 1 が閉じる（単独）。
5. **扉 1 を開けるのは人**：Unity の枠の「店内に戻す」を押す。ハブにつながり直す。
6. **扉 2 は人が開け、自動で閉じる**：ハブで `open` と打つ。枠の扉 2 が「Google Drive へ書き出し中」になり、数秒で閉じる。同期フォルダに記録ができる。
7. **緩めるのは人**：`--relax-after` の 60 秒揺れがなければ「提案」が出る。「承認して元に戻す」を押す。

## Unity 側（`GuardianHubLink`）

| 画面の項目 | 内容 |
|---|---|
| 扉1 | 開いているか、単独か。閉じたときはその理由。「単独にする」「店内に戻す」のボタン |
| 扉2 | 閉じているか、Google Drive へ書き出し中か |
| 監視AI | 学習中、見張り中、応答なし（3 秒助言が来ない）のどれか。応答がなくても、下げた速度はそのまま |
| 速度を下げているところ | 場所かロボット、倍率、理由。提案があれば「承認して元に戻す」「見送る」、なければ「人の判断で元に戻す」 |
| 対応のおすすめ | 故障したロボット、状況、推薦する人と着くまでの時間、経路、次点。経路は床に緑の線で描く |

- Unity は 127.0.0.1 につなぎにいくだけで、接続を受け付けません。ファイアウォールの確認は出ません。
- ハブとつながったあとは、ほかのウィンドウを選んでいてもシミュレーションを止めません（`Application.runInBackground`）。ハブを使わないときは、Unity の動きは今までと同じです。
- バッチモードの自動検証では、`-robomoriHub` を付けないかぎりつなぎません。

## やりとりの形

1 行に 1 つの JSON（UTF-8、改行で区切る）。Unity の `JsonUtility` で読み書きできるよう、入れ子の配列は使いません。

- Unity → ハブ（0.5 秒ごと）`telemetry`：ロボットの位置・速さ・状態・仕事・揺れ・今の速度上限、店員の位置と手のふさがり、人が決めたこと（`approved` / `declined` / `restored`）
- ハブ → Unity（0.5 秒ごと）`advice`：扉 2 の状態、監視 AI の状態、速度を下げるロボットと場所、戻す提案、対応のおすすめ

ハブは、NaN や Infinity、BOM、CRLF、長すぎる行、型や範囲の合わない値があっても止まりません。使えない値は「なし」として扱い、行ごと使えないときは数えて捨てます。Unity も同じように、使えない助言は捨てて数えます。

詳しくは [`protocol.py`](protocol.py) の先頭を見てください。

## テスト

```bash
python -m unittest discover -s scripts/guardian_hub
```

31 件あります。対象は、Unity が出す形の行の読み取り、監視 AI の判断、推薦の経路（店内の配置は `layout.py`。Unity のシミュレーターの値を写したもの）、扉 1 の訓練、ハブの記録の書き出し、扉 2 の外とのやりとりです。

## 限界

- シミュレーターのロボットの揺れは、ロボットごとの値です。場所による揺れの違いは、`--simulate-bump` の模擬でしか作れません。実機では、M5StickS3 の値を位置と合わせて送る必要があります。
- 店員以外の人（保守担当、管理者、調理担当）は、Unity の中に体がありません。ふだんいる場所にいるものとして計算します。
- 倍率やしきい値は試作の値です。実際の店で使うには、機体・床・荷物に合わせた調整と安全評価が必要です。
