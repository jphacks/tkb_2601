# 見守りの画面と共有（Robomori core）

[← README に戻る](../../README.md)

Unity のシミュレーターとは別に、この PC のブラウザで開く画面の説明です。ロボットの状態と仕事の割り当ては Unity が担当し、この画面は Unity からデータを受け取って表示する、**独立した監視用の仕組み**です。Robomori core が止まっても、Unity の配膳はそのまま動きます。

- **見守りのダッシュボード**：Robomori core（Docker）。この PC のブラウザで、起動ごとのワンタイムパスワードで入る
- **記録のビューア**：[`core/viewer/index.html`](../../core/viewer/index.html)。ロボもりのサーバーを使わず、AT プロトコルの公開の窓口だけで記録を読む

起動のしかた・設定・確かめたことの細かい記録は [core/README.md](../../core/README.md) にあります。

## 画面の中身

ダッシュボードには、Unity から届いた、いまの値だけを出します。Unity がつながっていないときは、Unity の代わりに同じ形のデータを送る模擬プログラム（sim）の値を出します。

| ところ | 中身 |
|---|---|
| ① 測る | Unity から届いた様子（ロボットの数・お客さんの数）、ロボットごとの揺れの推移（点線が注意のしきい値）、M5StickS3 の段階、PSoC 6 の承認待ち |
| 接続ゲート | 扉 1・扉 2 の状態（ネットワークから切り離した状態・店内だけ・外部）、接続してよい時間帯（時間割）、扉を開け閉めした記録 |
| 店内の地図 | Unity のシーンから読んだ配置に、0.5 秒ごとのロボット・お客さん・店員、席の空き具合、監視 AI が速度を下げた場所、対応のおすすめの道のりを重ねる |
| ② 判断する | ロボットごとに任せている仕事と、ロボット自身の説明 |
| ③ 改善する | 監視 AI が自動で厳しくしたもの、人の承認を待つもの、対応のおすすめ |
| ロボットとのやり取り | Unity でロボットに聞いたことと、ロボットの答え |
| 外部への共有（AT プロトコル） | 扉 2 で何を出し、誰の返信を受け取るか。次に SW2 を押したら外に出る文と記録の中身 |
| Google Drive の記録 | 書き出した要約の受信箱 |

## 見守る：ルール AI と監視 AI（外部の AI や API は使わない）

**ルール AI**（[`core/guardian/rules.json`](../../core/guardian/rules.json)、[`rulebot.py`](../../core/guardian/rulebot.py)）は、`rules.json` に書いた数字だけで、ロボットごとと店全体を「安全 / 注意 / 危険」に分けます。

- ロボットごとのルールは 8 つです（止まった回数、注意・制限になった回数、止まったままの時間、M5 の実測で上がった回数、KEY2 で戻した回数、センサーの途切れ、揺れの最大など）。店全体のルールは 3 つです。
- 判断には、根拠の数字と、人がすることを付けます。注意が 3 つ重なったら危険とみなします。
- 「いま危ない？」「B は？」と聞くと、決まった形で答えます。同じ様子と同じ質問なら、いつも同じ答えです。
- `rules.json` を書き換えると、次の質問から使われます。

**監視 AI**（[`scripts/guardian_hub/`](../../scripts/guardian_hub/README.md)）は、全部のロボットの動きを見比べて、動き方を直します。

| 見つけたこと | 判断 | すること |
|---|---|---|
| 同じ場所で 2 台以上が揺れた | 場所の問題（床の段差など） | その場所（半径 1.8 m）を通るときの速度の上限を 0.6 倍にする |
| 1 台だけが、場所を変えても揺れる | 機体の問題 | そのロボットの速度の上限を 0.7 倍にし、点検を勧める |
| しばらく揺れがない | 戻してよさそう | 元に戻す**提案**だけを出す。戻すかどうかは人が決める |
| ロボットが止まった、荷物を載せたまま動かない | 人が行くべき故障 | 店内の通り道のグラフで最短経路（ダイクストラ法）を求め、早く着く人を 1 位と次点で推薦する |

「揺れた」は、ロボットごとに学んだふだんの値（指数移動平均）との差で決めます。学習済みのモデルは使わないので、なぜその判断になったかを毎回文章で示せます。

## 閉じる：扉 1 と扉 2

扉 1 は、ロボットと店内 PC のあいだの通信を切ったりつないだりする仕組みです。扉 2 は、店内 PC からインターネットに出る、ただ 1 つの通り道です。

| 扉 | 閉じる | 開ける |
|---|---|---|
| 扉 1（ロボットと店内 PC のあいだの通信） | 使えない指示が 10 秒に 3 回届いたら自動で閉じる。ネットから届く指示で効くのは減速だけで、速度を上げる指示や範囲外の値は捨てる | 人が理由を確かめて「店内に戻す」を押したときだけ |
| 扉 2（店内 PC からインターネットへの出口） | やりとりが終われば自動で閉じる。扉 2 のコンテナも出口の中継も消える | 人が PSoC 6 の SW2 を押したときだけ。人が前もって決めた時間割が許す時間に限る |

- 扉 1 の決まりは、Unity の代わりにデータを送る模擬プログラム（sim）でも同じように動き、この公開リポジトリで確かめられます。
- Robomori core のコンテナは、インターネットへの経路がないネットワークにいます。インターネットに出られるのは出口の中継（[`core/egress/`](../../core/egress/)）だけで、通すのは許可した 3 つの宛先への HTTPS だけです。
- 画面には、起動ごとに出すワンタイムパスワードで入ります。8 文字、1 回限り、10 分で切れ、データベースにはハッシュ（scrypt）だけを残します。この PC 自身からの接続しか通しません。
- 監査ログは足すだけで、管理画面からも直せず、消せません。

## 共有する：会社の鍵でしか開けない記録を、AT プロトコルで

扉 2 を開けると、店のアカウントのリポジトリに、独自の形（Lexicon `internal.robomori.report`、[`core/lexicons/`](../../core/lexicons/)）の記録を 1 件置きます。

- **既定は「会社だけ（暗号化）」です。** 中身を 1024 バイト単位まで埋めて AES-256-GCM で暗号化し、宛先ごとに使い捨ての ECDH P-256 と HKDF-SHA256 で鍵を包みます（[`seal.py`](../../scripts/guardian_share/seal.py)）。Bluesky、PDS、ロボもりのサーバーには、中身は読めません。
- 宛先の人は、[`core/viewer/index.html`](../../core/viewer/index.html) を開いて鍵を作ります。秘密の鍵はブラウザの中だけにあり、取り出せません（WebCrypto）。
- 記録は 1 つ前の記録を指すので、順にたどれ、指した記録が書き換えられたら分かります。ただし、記録ごと消されたことや、古い履歴を見せられたことまでは、これだけでは分かりません。
- 保守会社がビューアに会社を並べると、自分の鍵で開けた記録だけを会社ごとに数え（危険・注意の件数、揺れの最大、KEY2 で戻した回数）、修理の相談か買い替えの提案かを出します。
- 会社 1 社に AT プロトコルのアカウント（DID）を 1 つ割り当てます。デモ用に、社内 VPN の中に置くデータ置き場（PDS）の代わりを同梱しています（[`core/vpnpds/`](../../core/vpnpds/)）。
- 外部に出すのは要約だけです（場所の名前、ロボットの記号、状態、速度の倍率、推薦）。座標や生の測定値は出しません。
- Google Drive へは、PC の Google Drive for desktop の同期フォルダに要約を写すだけです。コンテナは Google の鍵を持ちません。
- 店が選んだときだけ、扉 2 で要約を Gemini に送り、意見を聞きます。その意見は「提案」として画面に出すだけで、ロボットの動きは変えません。

| ファイル | 読みどころ |
|---|---|
| [`core/guardian/rules.json`](../../core/guardian/rules.json) | ルール AI の基準。ルールごとのしきい値、数える時間の幅、理由、人がすること |
| [`core/guardian/rulebot.py`](../../core/guardian/rulebot.py) | `rules.json` だけで「安全 / 注意 / 危険」を決め、質問に決まった形で答える |
| [`scripts/guardian_hub/monitor.py`](../../scripts/guardian_hub/monitor.py) | 監視 AI。ふだんの揺れの学習（指数移動平均）、場所の問題と機体の問題の見分け、速度の上限 |
| [`scripts/guardian_hub/dispatch.py`](../../scripts/guardian_hub/dispatch.py) | 故障したときに向かう人の推薦（ダイクストラ法） |
| [`scripts/guardian_hub/protocol.py`](../../scripts/guardian_hub/protocol.py) | Unity とのやりとりの形。使えない値や行を捨てる |

| [`core/egress/egress_proxy.py`](../../core/egress/egress_proxy.py) | 扉 2 の出口。許可した宛先の HTTPS だけを通す |
| [`scripts/guardian_share/seal.py`](../../scripts/guardian_share/seal.py) | 会社と保守会社の鍵でしか開けない暗号化 |
| [`core/lexicons/internal.robomori.report.json`](../../core/lexicons/internal.robomori.report.json) | AT プロトコルに置く記録の形 |
| [`core/viewer/index.html`](../../core/viewer/index.html) | ロボもりを使わずに記録を読むビューア |
| [`core/vpnpds/pds.py`](../../core/vpnpds/pds.py) | デモ用の社内 PDS の代わり |

## 限界

- 監視 AI は、同じ場所で複数台が揺れたら床の問題と推定しますが、因果関係を確かめたわけではありません。
- 記録の連鎖で分かるのは、指した記録の書き換えまでです。記録ごと消されたことや、古い履歴を見せられたことまでは分かりません。
- 中身は暗号化しても、誰がいつ記録を出したかは、公開の場から推測されえます。
- Google Drive へ写す要約は暗号化していません。
- Bluesky と Gemini とのやりとりは、偽の Bluesky・PLC・PDS と試し運転で確かめました。

研究としての論点は [docs/RELATED_WORK.md](../RELATED_WORK.md#6-記録の共有at-プロトコルの論点) にまとめています。
