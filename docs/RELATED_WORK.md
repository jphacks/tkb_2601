# 関連研究と、ロボもりの位置づけ

ロボもりの研究としての核は、ロボットの故障を見つけることそのものではありません。**不調を見つけたときに全部を止めず、残っている能力に合わせて仕事を配り直し、安全と稼働を両立させる**ことです。

この資料では、その考え方に近い先行研究を整理し、ロボもりとの違いと、これから研究として確かめることをまとめます。

- 文献の書誌情報（題名・著者・誌名・年・DOI）は、2026-10-25 に Crossref と各出版社・SEI のページで確かめました。
- 中身の説明は、各論文の要旨（abstract）に基づきます。ただし Yan ほか（2026）と Zhou ほか（2024）は要旨を読めなかったため、題名と書誌から分かる範囲で書いています。本文は読んでいません。
- 新規性については、まだ仮説の段階です。網羅的な先行研究の調査で確かめる必要があります。

## 1. 関わる研究領域

| 研究領域 | ロボもりで対応するところ |
|---|---|
| 故障に強いロボット（Fault-Tolerant Robotics） | 不調でも、できる仕事は続ける |
| 予知保全・健全性管理（Prognostics and Health Management, PHM） | 外付けの IMU で揺れを測り、不調を見つける |
| しなやかな複数ロボット系（Resilient Multi-Robot Systems） | 複数のロボットのあいだで仕事を配り直す |
| 実行時の安全保証（Runtime Assurance） | 危ない仕事を、動いている最中に制限する |
| サイバーフィジカルセキュリティ | ネットから届く不正な指示を締め出す |
| 人とロボットの協働（Human-Robot Interaction） | 戻すことと外へ出すことを、人が承認する |

## 3. 既存研究とロボもりの違い

| 比べる相手 | 既存研究の主な対象 | ロボもりが狙うところ |
|---|---|---|
| 仕事の割り当て（MRTA）の研究 | 効率のよい割り当て | 不調のときに、許された仕事だけで配り直す |
| 能力の劣化を扱う研究 | 劣化と修理の最適化 | 外付けのセンサーで状態を決める |
| 実行時の安全保証 | 制御の安全を守る | 仕事の種類まで制限する |
| 予知保全 | 故障を見つけ、保守の時期を予測する | 不調の間も、できる仕事を続ける |
| サイバーセキュリティ | 攻撃・侵入・改ざんへの対策 | 外から測ることと、ネットからの指示の権限を絞ること |

大事なのは、**能力の劣化を考えた仕事の割り当てそのものは、すでに研究されている**ことです（Yan ほか 2026、Zhou ほか 2024、Mayya ほか 2021、Cline ほか 2026）。「不調でも動かせるロボット」というだけでは、研究としての新しさは足りない可能性があります。

一方で、次のものを 1 つの仕組みにまとめ、実機で数字を使って評価した研究には、まだ余地があると考えています。

- ロボットの外に付けた IMU で状態を決める
- 状態を、仕事の種類ごとの許可に置き換える
- 運んでいる物（皿）の持ち主を保ったまま引き継ぐ
- ネットから届く指示の権限を絞る
- 元に戻すことを人が承認する

これは今の時点では新しさの**仮説**で、網羅的な先行研究の調査で確かめる必要があります。

## 5. これから研究すること

### A. 揺れから「できる仕事」を見積もる

今は 300 mg という試作のしきい値で状態を分けています。けれど本当に知りたいのは、揺れの大きさそのものではなく、**載せた物にどう響くか**です。同じ揺れでも、スープの液面、皿のすべり、重心の高い荷物では、危なさが違います。

IMU の RMS に加えて、周波数の成分、速度、加速度、載せた重さを使い、仕事ごとの失敗の確率を見積もる研究が考えられます。

### B. 不調のときの、よりよい配り直し

今の能力表を土台に、作業時間・移動距離・故障のリスクを同時に考える数理最適化へ広げます。たとえば目的関数は次のように置けます。

$$
\min \; \left( \alpha T + \beta R + \gamma H \right)
$$

$T$ は仕事が終わるまでの時間、$R$ は安全上のリスク、$H$ は人が手を出す負担です。係数は、使う現場の条件に合わせて決めます。

### C. 安全を保証できる状態の移り変わり

Normal・Warning・Limited・Hold の 4 つの状態について、単なる決まりとしてではなく、**どの移り変わりでも、禁止された仕事が実行されない**ことを検証します。Simplex の考え方、形式手法、実行時検証（Runtime Verification）が手がかりになります。

### D. 外付けセンサーで見つけることの確かさ

ロボット本体が報告する情報と、外付けの IMU の測定が食い違ったとき、どちらを信じるかという問題です。外付けのセンサーも、壊れる、外れる、書き換えられることがあるので、外から測るだけで安全を保証できるわけではありません。

## 6. 実機の PoC で測る指標

| 指標 | 中身 |
|---|---|
| 仕事を続けられた割合 | 異常が起きたあとも、終えられた仕事の割合 |
| 危ない仕事を実行した割合 | 制限すべき仕事が、実行されてしまった割合 |
| 配り直しにかかった時間 | 異常を見つけてから、別のロボットへの割り当てが終わるまで |
| 誤検知の割合 | ふつうの走りを異常と判定した割合 |
| 見逃しの割合 | 危ない状態を正常と判定した割合 |
| 人が手を出した時間 | 確かめる・決める・戻すのにかかった時間 |

実験では、少なくとも次の 3 つを比べると、ロボもりの利点と限界が見えやすくなります。

1. 異常のときに全部止める方式
2. 異常を無視して続ける方式
3. ロボもりの方式

どれも、安全を確保したシミュレーションか、管理された試験の場で比べることが前提です。

## 7. まとめ：研究テーマの候補

> **外からの測定に基づく、残っている作業能力の見積もりと、安全の制約つきの複数ロボットの動的な仕事の配り直し**

故障診断・制御工学・組合せ最適化・ロボットの安全工学にまたがるテーマです。研究として進めるなら、まず揺れと実際の作業の失敗の関係を測り、その結果で能力表を数字にすることが大事です。その先に、配膳ロボットから工場の AMR・AGV、さらに能力の違うロボットの群れへの展開が考えられます。

[Award Day に向けて](../README.md#award-day-に向けて) で作る「配膳ロボットに近い環境を再現したハード」は、この 5-A と 6 の測定の土台になります。
