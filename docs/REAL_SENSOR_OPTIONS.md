# 使用センサーと測定上の注意（M5StickS3）

実装済みの実機連携は、M5StickS3 の内蔵 BMI270 で振動を測る構成です。この文書は現在使う機材と信号だけを記載し、他機種の候補一覧や未実装の接続案は含めません。

## 使用する構成

| 部分 | 使用するもの | 役割 |
|---|---|---|
| 計測端末 | M5StickS3（M5Stack StickS3） | センサー計測、画面表示、ボタン入力 |
| 内蔵マイコン | ESP32-S3-PICO-1-N8R8 | ファームウェアの実行と USB シリアル出力 |
| 内蔵 IMU | Bosch BMI270 | 加速度の取得 |
| ファームウェア | Arduino / M5Unified | 振動 RMS・ピーク・傾きの計算と JSON Lines 出力 |
| PC の中継 | Python / pyserial | USB シリアル受信、状態判定、Unity への TCP 送信 |

マイコンと IMU は M5StickS3 の内蔵部品です。別々の基板を追加するものではありません。内蔵ハードウェアの詳細は [M5Stack の公式仕様](https://docs.m5stack.com/en/core/StickS3) を参照してください。

## 信号と判定

ファームウェアは加速度から重力成分を追従して除き、送信間隔ごとに振動の RMS とピークを集計します。傾き、基準値との比率、ボタン操作なども出力しますが、中継のレベル判定に使うのは振動 RMS の `vib_rms_g` だけです。

| 出力・操作 | 中継での使い方 |
|---|---|
| 振動 RMS | 閾値以上の状態が続いた回数から Warning / Limited を判定 |
| 振動ピーク・傾き・基準値比 | 現行のレベル判定には使わない |
| KEY1 | 端末での基準計測。中継の判定閾値を変更する操作ではない |
| KEY2 | 有効な測定値が届いているとき、人の操作で Normal へ戻す |
| 測定値の途絶 | 対象ロボットを Hold にする |

揺れが収まっただけでは、自動で Normal に戻しません。計測と人の復帰操作を分けています。

## 通信経路

```text
M5StickS3 → USB シリアル → Python 中継 → TCP → Unity
```

測定値とイベントは JSON Lines で送ります。中継と Unity の接続先は `127.0.0.1:47610` です。端末の Wi-Fi 機能を使う構成や UDP 送信は、今回の実装構成に含めません。

実機連携のファームウェア・中継・Unity の接続受け口は、この公開リポジトリには未収録です。公開版の模擬入力による確認と、実機連携の動作確認は区別してください。

## 測定時の確認

- 端末の固定方法、向き、床や対象物の動きが測定値に影響するため、取り付けた状態で確認します。
- 静置、通常の動き、揺らした状態を比較し、測定値が何を表しているか確かめます。
- KEY1 の基準計測を行っても、中継が振動 RMS の絶対値を判定する仕様は変わりません。
- メーカーの部品仕様やシミュレーターの結果から、実機での安全性や故障検出精度を保証することはできません。

接続とボタンの確認手順は [実機連携ガイド](HARDWARE_ASSEMBLY.md) を参照してください。
